# TopGrade Platform

Student practice app served at **https://app.topgradeedu.com**. No account needed. It is a Progressive
Web App: installable, works offline, and ready to be wrapped for Google Play as a Trusted Web Activity.

## Screens and URLs

| URL | Screen |
|---|---|
| `/` | Home: stats (streak, answered, accuracy), continue where you left off, courses, quick quiz, WhatsApp |
| `/courses` | Course list |
| `/courses/<course>` | One course and its topics with progress |
| `/courses/<course>/<topic>` | Topic: quiz setup → questions → results → review |
| `/review` | Mistakes to practise, across all topics |
| `/privacy` | Privacy policy (required for the Play Store listing) |

`/quiz.html` (the old single-course page) redirects to the Topic 1 URL.

## Layout

```
public/                         Published as-is (no bundler)
  index.html                    App shell for every URL (<base href> sets the base path)
  manifest.webmanifest          PWA manifest
  sw.js                         Service worker (offline); file list generated by `npm run build`
  assets/css/base.css           Fonts, brand tokens, element defaults
  assets/css/app.css            All app styles
  assets/icons/                 App icons (any + maskable), link-preview image
  assets/js/app/                App: main (routing), router, routes, shell, catalog, progress, quiz, views/
  assets/js/quiz/               Quiz engine: bank format, grading, sessions, saved runs, dialogs, DOM helpers
  data/catalog.json             Courses and topics, each topic pointing at its question bank
  data/<course>/<topic>.json    Question banks
tools/import-bank.mjs           Text question bank → JSON
tools/build-sw.mjs              Regenerates the offline file list/version in public/sw.js
tests/                          Unit tests (node --test)
```

## Adding a course or topic

1. Write the questions as text (format below) and import them:
   `node tools/import-bank.mjs bank.txt public/data/<course>/<topic>.json --course-id <course> --course-en "..." --course-ar "..." --topic-id <topic> --topic-number N --topic-title "..."`
2. Add the course/topic to `public/data/catalog.json` (`bank` is the path under `data/`).
3. `npm run build` then `npm test`. The tests check the catalog, every bank, and that `sw.js` is current.

## Quiz behaviour

- **Practice**: pick an answer, tap Check, see right/wrong with the correct answer.
- **Exam**: no feedback until the end; the question map jumps between questions and submits.
- Question order and option order are shuffled every run; options like "All of the above" stay last.
- Fill in the blank shows four words: the answer plus three distractors from the question's `Choices:` line,
  or else from other blanks' answers in the same bank (capitalised to match).
- A matching set counts as correct only when every pair is right.
- `explanation` / `source.page` on a question are shown with feedback and in the review.

## Language and theme

- The header is built once and never changes: theme switch, logo, language switch. Page-specific controls
  (back, close, titles, actions) live in each screen's page bar below it.
- **Languages**: English and Arabic (right-to-left), in `assets/js/app/i18n.js`. Every string has both
  versions (a test enforces it); Arabic plurals use `Intl.PluralRules`. Question content stays English and
  left-to-right inside the Arabic interface (`enText()` in shell.js). Course names show Arabic first in Arabic
  when the catalog has `titleAr`.
- **Theme**: light / dark (`assets/js/app/theme.js`, `[data-theme=dark]` tokens in app.css). Follows the
  phone's setting until the student picks one. An inline script in index.html applies the saved language
  and theme before first paint, so nothing flashes.

## Install (PWA)

The home screen offers installation when it makes sense (`assets/js/app/install.js`):
- **Android / desktop Chrome**: an "Install app" button that opens the browser's install dialog.
- **iPhone / iPad** (no install prompt exists): two steps, Share → Add to Home Screen.
- Hidden when already running installed, or for 30 days after the student closes it.

iOS notes: requires iOS 15.4+ (`<dialog>`, `:has()`, `100dvh`). Form controls use 16px text so Safari doesn't
zoom on focus. An app added to the home screen keeps its own storage, separate from Safari's.

## Progress (on the device)

Stored in `localStorage`, never sent anywhere:
- Per question: right/wrong counts. A wrong answer adds it to **mistakes**; two right answers in a row clear it.
- Per topic: best score (full quizzes only), mastered % (questions answered right at least once).
- Practice days, for the streak. An unfinished quiz is saved and offered as Resume for 7 days.

Answers are part of the page data, so they can be read in the browser. That is fine for practice; graded
exams would need server-side checking.

## Question bank text format

```
1) MCQ
Q1
Computer science is the study of:
A. Computers only
B. Algorithms
Answer: B

2) True / False
Q1
An infinite loop runs forever.
Answer: True

3) Fill in the Blank
Q1
The second generation used ________ instead of vacuum tubes.
Answer: transistors | transistor        ← "|" lists other accepted answers
Choices: diodes | relays | gears        ← optional; words shown with the answer

4) Matching
Matching 1 — Generations
1. First generation<TAB>A. Integrated circuits
2. Third generation<TAB>B. Vacuum tubes
Answers:
1 → B
2 → A
```

`---` separator lines are ignored.

## Develop and deploy

```
npm run build      # after any change in public/: refresh the offline file list
npm test           # unit tests
```

Preview locally with any static server that falls back to `index.html` for unknown paths (like the nginx config).

On the server:
- `tg-app-deploy --preview` publishes the working tree to `https://app.topgradeedu.com/preview/`.
- `tg-app-deploy` pulls `main`, tests, and publishes to the live site (and removes the preview).
- `tg-app-deploy --no-pull` publishes the local working tree to the live site.

nginx (`/etc/nginx/sites-available/app.topgradeedu.com`) serves `index.html` for app URLs, real files under
`/assets` and `/data` (404 if missing), and keeps `/.well-known/` open for Android's `assetlinks.json`.

## Google Play (later)

The Play Store app will be a Trusted Web Activity of this site (e.g. built with Bubblewrap or PWABuilder).
Needed then: a Play developer account, a fixed package name (e.g. `com.topgradeedu.app`), Play App Signing,
and `public/.well-known/assetlinks.json` with the app's signing certificate fingerprint.
